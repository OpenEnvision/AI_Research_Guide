# 找资料和读论文

文献调研帮助我们理解一个问题已有的证据：目前知道什么，不同工作采用了哪些假设与方法，还有哪些问题尚未回答。阅读时记录主要主张、证据来源与疑问，为下一步实验和判断提供依据。

<h2 id="reading-overview">了解一个领域</h2>

先通过综述、课程或报告了解主要问题与术语，再围绕一个问题阅读基础工作和后续论文。弄清这项工作为何提出、改变了什么，还有哪些问题尚未解决。作者主页和技术博客可以补充背景，具体发现仍应在原始工作中核对。

开始前不必了解全部细分领域。围绕一个问题选取少量论文，在阅读、讨论和检查实现的过程中不断修正理解。研究判断建立在对理由与证据的比较上，而不只是记住更多论文题名。

## 查找论文与相关工作

<a id="research-map"></a>

刚接触一个研究主题，可以先通过综述和课程熟悉基本术语，再用原始论文核对方法与结果。AI 可以协助生成检索词、整理候选论文和解释术语；**题名、作者、版本、发表状态和具体论断，都要回到论文原文与正式记录中核实**。一段流畅的摘要不能替代对证据的阅读。

[Google Scholar](https://scholar.google.com/) 可以查论文的后续引用与相关工作；论文中的参考文献则能找到它所依赖的前人工作。作者主页、项目页和代码仓库常有报告、演示与后续更新。检索功能见 [Scholar 官方说明](https://scholar.google.com/intl/en/scholar/help.html)，[AMiner](https://docs.aminer.cn/user-guide/platform-overview/) 也提供论文检索与阅读功能。更多方法见[定向文献检索](irene-workflow.md#search)。


<a id="search-protocol"></a>

### 把检索变成可以更新的记录

1. **先写问题，再列同义词。** 例如研究检索失败，可以分别查任务名、retrieval failure、query reformulation、hard negatives，以及领域特有叫法。记录英文缩写和相邻领域的术语。
2. **先宽后窄。** 综述帮助梳理研究脉络；经典原始论文说明最初的问题；近期论文反映研究条件的变化。分别查支持、反驳和复现该观点的工作，避免只收集与自己想法一致的文章。
3. **前后追踪。** 向后读参考文献，向前读引用它的文章，再检查作者主页、会议论文集、附录、项目页与代码版本。Scholar 支持题名引号检索、`author:`、年份筛选与引用追踪，具体用法见[官方检索帮助](https://scholar.google.com/intl/en/scholar/help.html)。
4. **保存检索范围。** 留下日期、数据库、查询式、纳入理由与排除理由。课程项目不应随意称为“系统综述”；如果没有覆盖全部文献，就明确这是一份围绕某个问题的调研。

### 原始论文、预印本和同行评审

原始论文直接报告作者的方法、数据或分析；综述和博客帮助解释背景。引用一个具体发现时，尽量追到产生该发现的原始工作，并读到对应图表或论证。

预印本可能尚未同行评审，也可能与已发表版本同时存在。[arXiv 官方说明](https://info.arxiv.org/help/moderation/index.html)明确区分内容审核与同行评审。查询会议论文集、期刊页面或 OpenReview 的正式决定，记录你实际阅读的版本；不要从“在 arXiv 上”推断“未发表”，也不要从“已接收”推断结论已被独立复现。版本间的方法和数值可能变化，应按所引用的版本核对。

<a id="reading-depth"></a>

## 读到什么程度

**阅读深度取决于这次想弄明白什么。** 了解一项工作时，先关注问题、主要方法和关键结果；梳理一个方向时，要比较工作之间的联系；准备复现或改进，则需要细看架构、公式、数据和实验设置。

同一篇论文也可以分几次读。第一遍留下的疑问，可能在看过后续工作、代码或实验之后才有答案。[Keshav 的 How to Read a Paper](https://cs.uwaterloo.ca/~brecht/courses/854-Experimental-Performance-Evaluation-2018/readings/common/how-to-read/keshav-paper-reading.pdf) 介绍了三遍阅读法；李沐的[如何读论文](https://www.bilibili.com/video/BV1H44y1t75x/)也谈到论文的阅读顺序与深度。


### 按阅读目的决定产出

| 层次 | 要回答的问题 | 留下的产出 |
| --- | --- | --- |
| 定位 | 研究对象、主要主张是什么，与我的问题相关吗？ | 一句话摘要、相关或排除理由 |
| 理解 | 输入输出、关键假设、方法步骤如何连接？ | 自己画的流程、符号表、一个例子 |
| 评估 | 比较是否公平，证据支持到什么范围？ | 主张—证据表、限制和替代解释 |
| 复现 | 数据、预处理、配置与评估能否落实到代码？ | 固定版本、最小运行命令、待确认差异 |

不必把每篇论文都读到复现层。遇到核心公式，先说清变量与假设，再用维度、边界情况或一个小例子检查理解；如果推导仍不成立，保留疑问，查前置教材或向合作者请教。

## 论文里的问题、方法与实验

从摘要、引言、关键图和结论开始，了解**做了什么、为什么做、怎么做**，再去实验里看结果怎样支持这些判断。方法细节和没弄懂的地方，可以回头再查。

<a id="claims-evidence"></a>

比如作者说一个模块带来了提升，就看看消融是否单独改变了这个模块；说能泛化到新场景，就找测试场景与训练数据的关系。比较几篇工作时，除了方法差别，还要看它们使用的**任务、数据和计算资源是否相同**。阅读中的疑问也可以拿来讨论，或[让 AI 围绕你的理解追问](ai.md#grill-me)。


### 对照主张与证据

| 论文主张 | 阅读时寻找的证据 | 仍需警惕的解释 |
| --- | --- | --- |
| 某模块有效 | 保持其他条件一致的消融及其预算 | 参数量、训练时长或调参机会一起增加 |
| 更高效 | 相同质量下的时间、显存、调用或 token 成本 | 硬件、批量、缓存和实现优化不同 |
| 泛化更好 | 与训练分布关系明确的新实体、时间或领域 | 测试集与训练集共享近重复或同一主体 |
| 更稳健 | 指定扰动、子群和失败率的分析 | 只挑选有利扰动或隐藏平均分背后的差异 |

表格是本指南建议的检查方式。它与 [NeurIPS checklist 的主张范围原则](https://neurips.cc/public/guides/PaperChecklist)一致：结论需要与实际理论或实验结果相称。**没有做过的对照应标为未知；未报告不等于无效。** 详细实验设计见[科研方法与实验设计](research-methods.md)。

<a id="paper-code"></a>

## 论文与代码

沿论文中的数据流阅读代码仓库。附录、配置和 issue 可能解释正文未写出的细节。代码说明某种实现，不自动保证实现或论文正确；调查差异前，先固定版本。

### 做一张论文到实现的对应表

挑一个样本，从数据入口跟到最终指标：原始文件 → 划分和预处理 → 模型输入 → 输出与损失 → 后处理 → 评估。记录论文段落、代码文件与函数、配置键及仓库 commit。先跑通一个小批量，再检查张量形状、标签含义和指标方向；不要把“程序运行结束”当成“复现成功”。论文与代码不一致时，分别记录事实、可能影响和你采用的处理，不替作者编造理由。

<a id="paper-notes"></a>

## 论文笔记与文献整理

[Zotero](https://www.zotero.org/support/quick_start_guide) 可以保存论文信息、PDF 和批注；Obsidian、飞书或 Notion 都可以用来整理自己的理解、疑问和相关材料。除了文章讲了什么，笔记里也值得留下**自己当时为什么关注它、哪些地方还没想明白**，连同相关图表和原文位置一起保存。Zotero 与 Obsidian 的配置和笔记示例见[论文与笔记工作流](irene-workflow.md#notes)。

几篇论文讨论同一个问题时，可以把它们放在一起，整理方法之间的联系、各自的实验条件和仍未解决的问题。随着阅读和实验推进，这些联系也会变化。[研究问题与相关工作](irene-workflow.md#depth)里有一种整理方式。


<a id="literature-matrix"></a>

### 用文献矩阵比较同一个问题

矩阵每行是一项工作，至少记录下列信息。信息缺失时标注“未报告”或“待核实”，不要用默认值填空。

| 字段 | 应记录什么 |
| --- | --- |
| 文献信息与发表状态 | 题名、作者、年份、DOI/arXiv、版本、正式发表记录 |
| 问题与假设 | 在什么任务、输入输出和适用条件下提出主张 |
| 数据与协议 | 数据版本、划分单位、是否额外预训练或检索 |
| 方法与参照 | 关键改变、有竞争力的基线、是否在公平条件下重新运行 |
| 结果与成本 | 指标定义、方向、波动、训练与推理预算 |
| 限制与证据位置 | 失败案例、未测试范围、页码/图表/附录 |
| 与我有关的下一步 | 能借用的代码或数据、要核查的差异、可测试问题 |

论文看似矛盾时，先比较任务、数据、假设、评估程序与预算。条件不同可以带来不同发现；不要将不可比的分数取平均或据此排名，也不要直接认为一个结果推翻另一个。记录还需要怎样的可比实验，才能解释这些分歧。综述分类同样是一种组织方式，可以随证据修改。

### 一份可核查的阅读笔记

```text
文献标识 / 阅读版本 / 阅读日期：
我为什么读：
一句话问题与主要结论：
作者的明确主张： [页码、节、图表]
支持主张的实验或推导： [设置、对照、结果位置]
数据、模型、预算与评估协议：
我的解释： [与原文陈述分开]
尚未确认： [未报告细节、替代解释、代码差异]
可执行下一步： [最小复现、对照、给作者的具体问题]
引用 / 改绘图的原始来源与许可：
```

AI 整理的每条事实也应附原文位置；找不到证据时保留“待核实”，不要把推测写成作者结论。直接引用的短句、自己的转述和判断应分别标明。参考管理器负责保存来源，研究笔记负责记录你如何从证据得出理解，两者可以互相链接。

<a id="reading-outputs"></a>

## 学完后应留下什么

读第一篇论文时，先留下一份笔记，写清问题、核心主张、证据位置和一个真实疑问。比较多项工作时再用文献矩阵；需要研究实现时，再做论文到代码的对应表。它们服务于不同目的，不是阅读每篇论文时都必须完成的四份文档。

向同伴解释这篇论文，请对方指出论证中仍不清楚的一环，再据此决定下一篇读什么，或需要核查什么。接下来可学习[实验设计](research-methods.md)；如果缺少必要的前置知识，可回到[课程地图](courses.md)查找相应内容。
