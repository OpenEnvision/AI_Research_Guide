# AI 学习路线：从基础到研究

理解知识之间的联系，有助于找到学习 AI 的方向。编程把方法写成可以执行的程序，数学解释其中的运算，机器学习将这些运算与数据联系起来，科研则追问证据能够支持什么结论。这些能力相互关联，也可以按照各自的进度逐步积累。

无论正在大学学习、转换研究领域，还是刚开始研究工作，都可以按当前理解程度决定下一步学什么，无需对应某个固定年级。[基础知识](basics.md)解释概念，[科研方法](research-methods.md)说明如何审视一项研究。在了解感兴趣专题的同时，按需要补充相关的先修知识。

<a id="route-start"></a>

## 从当前卡住的地方确定起点

可以从自己已经接触过的内容判断起点。你能否读懂一段短程序，理解它怎样把数据变成预测？如果卡在索引操作，就从编程开始；如果能读懂代码，却说不清矩阵乘法或导数的含义，就把相关数学知识与机器学习入门结合起来学习；如果计算过程清楚，却不知道结果是否可信，就从评估与科研方法入手。

可以用下面的依赖关系找方向：

| 先理解什么 | 它帮助你理解什么 |
| --- | --- |
| 函数与数组 | 数据和模型计算如何表示 |
| 向量与矩阵 | 线性预测、嵌入表示与神经网络层 |
| 导数与链式法则 | 基于梯度的学习怎样改变参数 |
| 概率与抽样 | 预测不确定性、数据划分与统计证据 |
| 简单监督学习模型与评估 | 深度学习增加了什么，以及一次比较说明了什么 |

编程与入门数学可以并行。更深入的数学随问题需要补充：理论证明需要明确假设与证明方法，序列决策需要进一步学习概率与优化。选择[课程](courses.md)时，再核对该课程自己的先修要求。

<a id="route-programming"></a>

## 编程：先理清数据，再理解模型

先学到能够阅读和修改一段小程序的程度：理解变量、容器、函数、循环、文件与异常，再学习[数组、形状与索引](basics.md#basics-arrays)。跟踪每个数组维度代表的是样本、特征还是其他含义，不能仅凭维度恰好匹配，就认为运算有意义。

例如，假设我们想按主题分类短文档。可以用一张表表示数据：每行对应一篇文档，每列对应一个词语特征。在学习分类器之前，应先解释文档如何变成一行数据，标签保存在哪里，以及筛选数据后，行与标签是否仍然对应。理解这些关系后，模型代码就不会显得那么神秘。

在实际需要时学习终端、隔离环境与基本 Git 操作。可以通过[练习平台](practice.md)做有针对性的小练习，无需先完成大量竞赛题。程序出错时，先追踪一个输入的处理过程，查看中间值，再决定是否需要更多工具或更复杂的方法。

<a id="route-math"></a>

## 数学：把每种工具与它回答的问题联系起来

[线性代数](basics.md#basics-linear-algebra)先学向量、点积、矩阵乘法和线性变换。在文档例子中，点积把特征与学得的权重组合成一个分数。先通过具体用途理解符号，再借助秩、特征值等概念深入理解表示与变换。

推导反向传播前，先理解[导数与链式法则](basics.md#basics-calculus)。导数描述局部敏感性：一个参数改变时，损失会怎样变化？链式法则把这种敏感性沿一串运算连接起来。先从一个参数和一个简单函数入手，再扩展到整个网络。

同时学习[概率与统计](basics.md#basics-probability)。条件概率描述给定已知信息时的关系，抽样则帮助解释：为什么已有数据上的结果，可能不同于未来数据上的表现。这些知识为理解估计与不确定性奠定基础。可以一边巩固这些知识，一边学习机器学习入门；当符号或假设成为障碍时，再回到对应推导。

<a id="route-ml"></a>

## 机器学习：把拟合与评估分开理解

从[监督学习](basics.md#basics-learning)和线性回归、逻辑回归等简单模型入手。区分模型的参数、拟合参数时使用的损失，以及判断预测质量的指标。训练损失降低说明模型对训练信息的拟合有所改善；在未见样本上的表现还需要另外的证据。

在文档分类中，同一作者或来源的文档可能共享容易被利用的线索。因此，随机划分与留出整个来源进行评估，可能回答不同的问题。把[训练、验证与测试](basics.md#basics-evaluation)放在具体任务中理解：评估希望代表怎样的未来使用情境？预处理与模型选择应限制在相应的训练和验证阶段内。

解释复杂模型的评估结果前，先与简单基线比较。查看哪些样本容易出错，以及指标怎样权衡不同错误。[第一个项目](start.md)可以让这些关系变得具体，[数据集与评测](datasets.md)进一步解释其中的选择。当你能够说明比较支持什么结论、证据又有哪些限制时，就可以继续深入。理解模型拟合、损失、指标与数据划分后，就可以开始学习[科研方法](research-methods.md#methods-start)，无需等深度学习课程全部学完。

<a id="route-deep-learning"></a>

## 深度学习：理解哪些改变了，哪些仍然相同

深度学习增加了学习表示的能力，以及更复杂的参数化函数；它仍然需要明确任务、合适的数据、目标函数与评估协议。经典模型仍是有用的比较对象，许多问题也无需大型神经网络就能研究。

把张量与数组、网络层与变换、自动微分与链式法则联系起来。理解前向计算怎样产生损失、梯度怎样用于更新参数，再看不同架构利用了数据的哪些结构：CNN 利用局部空间结构，注意力让表示能够组合来自其他位置的信息。

如果难以理解训练过程，就回到一个批次、一层网络或一次更新；如果训练表现改善而验证表现变差，就重新检查对泛化与模型选择的理解。学习曲线是需要解释的证据，本身不能给出唯一诊断。按实际需要，通过[研究工程](engineering.md)继续加深实现能力。

<a id="route-research"></a>

## 科研：围绕问题深入学习

用[研究方向地图](directions.md)找到关心的问题，再借助[论文阅读指南](reading.md)与[论文选读](papers.md)读一小组相关论文。先比较研究问题、假设与证据，再比较模型名称。

实证研究需要数据、可信的比较，以及对结果波动的理解；理论研究需要明确的定义、假设，以及能够支持所述结果的论证。许多项目会结合两者。复现或完整推导可以暴露尚未理解的地方。要形成自己的贡献，应指出还有什么问题没有回答，并说明自己的分析如何回答它。

例如，“文档分类器是否提高了分数？”可以进一步变成“改进在未见来源上是否仍然成立，哪些文档受益？”[研究问题的表述](research-methods.md#question-hypothesis)说明如何把问题与证据连接起来。再根据问题需要学习[专题知识](advanced-topics.md)、[负责任的 AI](responsible-ai.md)与[写作](writing.md)。

## 让路线保持可持续

为下一个概念选择一份主材料。学完后，不看笔记解释一个例子，再尝试稍有变化的例子。卡住时，判断缺的是定义、数学运算、编程细节，还是某一步缺少证据的推断。回到那个环节补充，向他人请教时也能提出更具体的问题。

用自己熟悉的语言学习，同时在笔记旁保留原始技术术语，方便检索。把翻译作为辅助，涉及假设、否定与局限时核对原文。可持续的学习安排需要留出回顾概念的时间；统一的完成期限或一长串已学课程，都不能代替理解。
