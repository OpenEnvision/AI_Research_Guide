# 科研入门：60 个问题

这份问答面向世界各地准备参与研究的大学生与初级研究者，覆盖学习准备、选题、指导关系、论文、实验、合作与发表。研究可以从一个具体问题和一次小规模尝试开始，再逐步提高方法与证据的质量。

**按当前任务打开相应问题即可。** 希望先动手，可以选择[入门项目](start.md)；希望制定系统计划，可从[学习路线](learning-path.md)开始。项目参与、申请与投稿要求，因机构、会议或期刊而异。

## 科研概况

<a id="q1"></a>

### 1. 科研是什么？与课程项目、竞赛有什么区别？

研究围绕尚未解决的问题增进认识，并给出他人能够检查的论证。证据可以是证明、测量、数据分析、实验，也可以是设计恰当、涉及人类参与者的研究。新数据集、可靠评估、复现或解释，与新方法一样，都可能成为贡献。

课程和竞赛通常给出任务与评分规则；研究还要说明问题为何值得问、与已有工作的关系，以及结论能覆盖什么范围。一个项目即使尚未形成研究贡献，也可以带来有价值的学习。


<a id="q2"></a>

### 2. AI 研究者除了读论文和写代码，还做什么？

日常工作包括文献检索、复现基线、设计实验、调试、分析、讨论、记录与写作。有时需要重新界定问题，或查明一个实现差异为何改变了结论。

一次实验应留下代码版本、配置、日志、指标与案例分析，便于下一步判断和他人检查。实验准备见[第 43 问](research.md#q43)。

<a id="q3"></a>

### 3. 科研能训练哪些能力？怎样结合升学或职业目标？

研究项目提供定义问题、比较文献、设计实验、分析结果、技术写作与合作的练习。好奇心、继续求学或职业探索，都可以成为尝试的起点。

涉及申请时，先查目标项目或岗位的正式要求，再准备相关作品和经历说明。论文、代码、学位与工作经验的要求各不相同；研究经历的价值应通过具体工作与能力呈现。

<a id="q4"></a>

### 4. 研究主要难在哪里？开始前容易低估什么？

常见困难包括问题仍不明确、基线无法复现、比较条件不一致、资源不足，或结果并没有回答最初的问题。选题、实现、分析和表达都需要反复调整。

开始前与合作者确认资源、评估方法、反馈方式和阶段目标。AI 可以帮助检索、编程与整理记录，实际效果取决于任务与核查；即使执行更快，仍需要清晰的问题定义和可靠的证据。

<a id="q5"></a>

### 5. 怎样通过小项目判断自己是否愿意继续研究？

选择一个范围合适的问题，以及一份可以核查的相关材料。例如，评议论文的主要比较、分析公开预测中的错误，或学习一个[入门项目](start.md)。实现是起点之一，不是探索研究的唯一入口。

如果运行项目，先理解输入、参照方法与评估。能够解释比较可以说明什么后，再尝试改变一个因素。留意哪些不确定性使自己愿意继续调查，并与同伴或指导者讨论。


## 科研准备

<a id="q6"></a>

### 6. 本科早期可以接触研究吗？怎样判断自己适合承担什么任务？

可以按任务层次判断：运行演示需要理解环境与输入输出；复现实验还需要理解数据划分、训练与评估；修改方法则需要进一步掌握原理和对照设计。先查具体项目的先修要求。

开始得早通常有更多探索时间，较晚开始也仍可建立研究能力。具体任务可能涉及安全、数据权限或专业要求，按当前能力选择范围，见[学习路线](learning-path.md)。

<a id="q7"></a>

### 7. 学校资源、语言能力或数学、编程基础有限，应该从哪里开始？

把“基础不足”缩小到一个具体障碍：能否运行 Python 示例、解释张量形状、区分训练与测试，或借助词典识别摘要中的主张？针对遇到困难的步骤查阅[基础知识](basics.md)，并安排相应练习。

课程、公开代码和开放交流提供了不同入口，指导与资源的可获得性仍存在差异。项目学习要配合必要的系统学习；影响实现正确性或评估的缺口，应专门补足。

<a id="q8"></a>

### 8. 联系潜在指导者前，需要准备到什么程度？

请教学术问题时，说明来源位置、当前理解与未解决之处即可。希望加入项目时，再补充相关课程、代码或复现记录、可投入时间，以及需要怎样的指导。

准备应与请求相匹配。没有必要学完所有 AI 课程才联系研究者，但应能清楚说明自己的尝试、现有能力和下一步计划。

<a id="q9"></a>

### 9. 还没有论文或项目经历，可以准备什么作品？

从一项小任务开始：可运行的复现代码、一页实验记录，或对一篇论文的结构化分析。说明自己做了什么、怎样检查，以及尚未解决什么；涉及论文论断时保留原文位置。

这些材料便于别人了解你的思考与准备程度。可以参考[联系邮件示例](contact.md)，准确陈述已完成的工作。

<a id="q10"></a>

### 10. 第一个月的探索可以怎样安排？

选择一个[入门项目](start.md)，按“确定任务与数据 → 运行基线 → 修改并比较 → 整理代码、结果与问题”推进。各步时间可以按基础与进展调整，每一步都留下记录。

结合[分阶段学习路线](learning-path.md)与[练习平台](practice.md)补充所需知识。完成一个小项目的全部流程，比同时启动多个项目却都未完成，更便于评估学习进展。

## 研究方向

<a id="q11"></a>

### 11. 怎样初步了解 AI 有哪些研究方向？

先看[研究方向地图](directions.md)中的任务、输入输出与代表工作，再选择一个具体问题。演示、媒体与社区讨论可以提供线索；对方法和能力的判断，应继续查论文、代码、评估条件与限制。

研究动态入口见[研究者与实验室](lookout.md)，课程和项目见[方向资源目录](catalog-directions.md)。热度与传播效果不能替代研究证据。

<a id="q12"></a>

### 12. 听说过 LLM、Agent、具身智能、RL、世界模型后，怎样进一步理解它们研究的任务？

用四个问题描述一个方向：**研究目标是什么，输入是什么，输出是什么，当前在哪些条件下失败？** 再比较论文提出的问题、方法、证据与已有工作。

每读完一篇文章，就为这些问题补充一项具体信息。逐步建立对任务和评估的认识，再深入模型结构。

<a id="q13"></a>

### 13. 怎样看清演示效果背后的实现条件与限制？

查看演示使用的数据、代码与评价：展示了哪些案例，有没有失败输入，是否存在人工干预，指标测量的能力是否与演示一致。

尝试复现一种可以检查的行为，并从中提出一个问题。对实现和失败条件的兴趣，有助于判断自己是否愿意深入研究。

<a id="q14"></a>

### 14. 比较研究机会时，怎样考虑兴趣、指导、资源与难度？

为候选项目列一张表：研究问题、相关工作、先修能力、实际指导者、可用数据与算力、阶段目标，以及尚未确认的条件。向项目联系人核实不确定项。

评估单次运行和调参成本、验证周期，以及假设不成立时仍能留下的学习成果。资源有限时可以缩小系统规模，研究评估、数据或失效分析。对照与预算见[实验设计](research-methods.md#baselines-budget)。

<a id="q15"></a>

### 15. 为什么要跟进不同机构的工作？具体看什么？

不同团队的工作会提供各自的方法、数据、实现和评估条件。围绕同一个问题比较：各项工作改变了什么，在什么条件下成立，仍然留下什么不确定性。

这样能建立领域脉络，发现可用方法与尚待解释的现象。研究入口见[研究者与实验室动态](lookout.md)。

## 学术联系

<a id="q16"></a>

### 16. 联系不同机构或地区的研究者，需要注意什么？

使用学校、实验室或作者主页公开的联系方式，遵循其研究咨询或申请说明。说明自己关注的论文或项目、已经做过的尝试，以及这次联系的具体请求。

跨机构或跨地区合作时，确认招募条件、是否接受远程参与、时区、工作语言与资源访问安排。可以先交流问题，再判断是否存在合适的合作机会。

<a id="q17"></a>

### 17. 从哪里找到相关研究者与入门研究机会？

从论文作者主页、实验室项目页和公开招募信息开始，查看研究主题、近期工作、参与要求与联系渠道。沿论文引用和合作者关系继续寻找相关团队。

过去指导过学生或初级研究者是一条线索，不能证明目前仍有空缺。确认谁负责日常指导，以及是否有时间提供所需反馈。

<a id="q18"></a>

### 18. 第一次联系可以提出什么请求？

可以请教论文中的一个具体问题、询问研究机会，或了解公开报告、旁听与短期试做安排。一条消息聚焦一个明确的请求。

希望约谈时，说明主题、相关材料与预期时长；希望参与项目时，说明兴趣、当前能力和可投入时间，见[联系与合作](contact.md)。

<a id="q19"></a>

### 19. 第一封邮件怎样介绍背景、尝试与来意？

说明自己的背景、相关研究、已经完成的尝试，以及这次请求。附上必要的代码、笔记或简历，区分已完成的成果与未来计划。

“阅读您的某项工作后，我对其中一个问题感兴趣，已经尝试了这些步骤，希望请教这个具体困难”，就能让对方判断是否可以提供帮助。完整示例见[学术联系](contact.md)。

<a id="q20"></a>

### 20. 没有回复、被拒绝或被安排试做时，下一步怎么办？

回复可能是交流邀请、阅读或试做任务，也可能是当前没有机会；没有回复也很常见。按对方说明准备，必要时隔一段合理的时间后，礼貌跟进一次，并继续了解其他机会。

接受试做前，明确任务范围、截止时间、反馈方式与成果用途。一次回复只提供这次机会的信息，应结合具体反馈改进准备。

## 课题组与指导关系

<a id="q21"></a>

### 21. 对方说“可以聊聊”，第一次交流准备什么？

准备简短介绍、相关作品和想问的问题，确认任务、日常联系人、指导方式、资源与时间安排。说明自己的基础、限制和仍需补足的能力。

交流也帮助你判断项目是否适合。会后整理已达成的约定与下一步，便于双方确认。

<a id="q22"></a>

### 22. 收到一篇“先看看”的论文，应该读到什么程度？

先确认任务是理解主要论证、做一次汇报，还是复现实验，以及何时讨论。

- **第一遍：**说明问题、方法、主要证据与未解决之处。
- **继续分析：**定位前序与后续工作，列出实现检查或可能改动。
- **跨方向比较：**寻找相似问题，并检查方法能否在相应条件下迁移。

阅读深度由任务决定，具体步骤见[文献阅读](reading.md)。

<a id="q23"></a>

### 23. 可以先旁听或试做，再决定是否加入吗？

可以询问是否允许旁听、短期试做或分阶段参与。开始前约定范围、时间、反馈、资源，以及成果将如何使用。

同时确认数据和材料限制、贡献记录，以及离开时如何交接。随着工作推进，按实际贡献与适用的发表政策重新讨论署名；早期沟通应澄清预期，而不是掩盖未来角色尚未确定的事实。


<a id="q24"></a>

### 24. 怎样确认谁负责日常指导、交流频率与资源？

直接问清：日常和谁讨论，多久同步一次，遇到困难联系谁，怎样使用数据与算力，每个阶段预期投入多少时间。

指导可能由教师、研究生或其他研究者承担，以项目的实际安排为准。说明自己的课程、工作和时间限制，形成双方能够执行的约定。

<a id="q25"></a>

### 25. 指导关系不合适或长期没有反馈，怎样调整与交接？

列明反馈、范围、资源或时间与约定的具体差异，先与日常联系人讨论调整。必要时通过合适的指导者或机构支持渠道进一步处理。

决定离开时，确认结束日期、已完成与未完成任务、代码和数据位置、交接对象，以及成果与权限的后续安排。让接手者清楚知道项目的当前状态。

## 基础知识与学习

<a id="q26"></a>

### 26. AI 研究有哪些共同基础？哪些要求取决于方向？

线性代数、概率与统计、微积分、优化、编程和计算机基础，通常是值得逐渐建立的共同基础；信息论与计算基础设施知识需要掌握到什么深度，则取决于任务。它们能让你更深入地理解技术的原理、理论和细节，也能为你正在做的事情提供指导。

例如，[预训练的超参数](llm.md)、后训练的数据配比、强化学习的规模扩展规律、计算机视觉和去噪扩散概率模型（DDPM），背后都有值得进一步理解的原理。学习强化学习时，理解策略梯度经常需要用到概率与期望；阅读 CNN、Transformer 的架构时，会涉及线性代数、张量运算和优化；训练和部署模型，又离不开计算基础设施。

暂时不熟悉这些术语也没关系。遇到具体问题时，再找对应材料，逐渐把它们和自己的工作联系起来。

按当前任务选择先修内容和练习，见[课程与先修关系](courses.md)；课程列表是学习资源，不能替代对自身理解与验证能力的检查。


<a id="q27"></a>

### 27. 学课程、读书、做项目，怎么搭配？我怎样避免一直准备，却迟迟没有开始？

**不必等一个方向的论文都读完，才打开代码。** 读到一个感兴趣、条件允许的项目，就可以把阅读和运行放在一起：用作者的示例看看模型输出，对照实现理解论文，再尝试改动其中一处。很多原本不知道为什么要学的知识，会在这时变成具体问题，回头补课程也更有着落。

把课程、阅读和项目围绕一个问题连接起来，见[学习路径](learning-path.md)。结课或平台证书可以记录学习经历，但不能单独证明理解深度或复现实验的能力；申请是否需要某项资格，应查具体项目要求，不必为了凑证书中断实质练习。


<a id="q28"></a>

### 28. 遇到一个不懂的概念，什么时候应该停下来系统补课，什么时候可以先了解大意？

先看它**是否影响实现正确性、关键假设或结果解释**。影响了就需要补到能够核查的程度；暂时不影响当前任务的推导可以记下，在修改对应方法或扩大结论前回头检查。不同任务需要的深度不同。

之后再回来补时，用现在的任务检验自己的理解。不要让“以后再学”一直停留在笔记中。


<a id="q29"></a>

### 29. 看完课程或运行代码后，怎样检查理解是否扎实？

做三项检查：

1. 解释数据流、损失与指标，并定位对应实现。
2. 修改一个设置，运行前写下预期，再与实际观察比较。
3. 针对一个失败案例提出几种解释，设计能区分它们的检查。

例如，听懂 TRPO、PPO-Clip 或 GRPO 的概括，还不足以验证实现。[PPO-Clip](https://arxiv.org/abs/1707.06347) 的裁剪替代目标抑制过大的策略变化，但不提供实际 KL 变化的普遍硬上界。涉及稳定性或效果的判断，应核对原始方法、假设和实现版本。

保留结果与尚未解决的问题，作为下一次学习和实验的依据。

<a id="q30"></a>

### 30. 在 AI 能解释概念、写代码的情况下，哪些基础仍值得自己花时间建立？

AI 可以承担越来越多的编程和资料整理工作，但研究经验与判断仍需要自己积累。数学、模型、计算机系统和实验方法仍然重要，因为它们影响你能理解什么、能看出什么问题，以及出现意外时能不能自己作出判断。

除了技术基础，讨论、表达和合作也很重要。一个结果为什么可信，一项方法为什么这样设计，实验里哪里可能出错——这些问题需要你能够和其他人讲清楚，也听懂别人的质疑。

多问 AI，也多和真实的研究者交流。让工具帮你完成事情的同时，尽量弄明白它做了什么、为什么这样做。否则，即使任务完成了，下一次遇到相似问题时，仍可能不知道从哪里着手。

## 论文检索与阅读

<a id="q31"></a>

### 31. 经典、综述、近期工作与指定论文，应该先读哪种？

按当前目的选择：综述或课程帮助熟悉术语与研究脉络，基础论文说明最初的论证，近期工作反映研究条件的变化，指定论文服务项目讨论。重要主张继续追到原始来源。

少量相互关联的工作通常比庞大清单更有帮助：一项核心方法、最接近的前人工作或替代方法，以及一篇检查重要限制的论文。视觉、语言、决策、理论和交叉学科都可以这样组织。先用[论文选读](papers.md#paper-selection)与[阅读深度指南](reading.md#reading-depth)选择，再在[文献比较](reading.md#literature-matrix)中记录版本和证据位置。


<a id="q32"></a>

### 32. 一篇论文打开之后先看哪里？第一次读完，至少应该能回答哪几个问题？

先看摘要、引言、关键图和结论，弄清做了什么、为什么做、怎么做，再检查实验如何支持这些主张。

在这个过程中，也要了解任务、数据、基线方法和评估指标。

<a id="q33"></a>

### 33. 英文、公式、术语和背景都看不懂，怎么办？哪些可以暂时跳过？

先把主要句子与概念读通。让 AI 解释术语，对照原文，也可以找作者讲解、视频和别人的笔记。

公式可以分层读：先知道各个量代表什么、这一步要完成什么，再看推导。如果某个公式是复现或改进方法的核心，就需要逐步理解它的含义与推导。

<a id="q34"></a>

### 34. 什么叫“读懂一篇论文”？需要理解每个推导、读完代码、复现结果吗？

第一遍能讲清问题、方法与主要证据，就已经有收获。若要复现或改进，还需要深入了解数据、实现、推导和评估细节。

<strong>阅读目的决定这一遍需要理解到什么程度。</strong>遇到关键疑问，留着回头验证。

<a id="q35"></a>

### 35. 读完以后怎么留下有用的东西？怎么把几篇论文联系起来，而不是各记一份摘要？

飞书、Notion、[Zotero、Obsidian](irene-workflow.md#notes) 都可以。工具选顺手的，笔记里留下自己的疑问和联系。

几篇文章之间，可以按同一个问题整理：它们分别改了什么，比较条件有什么不同，一篇的结论如何影响另一篇。读完再写几句自己的理解，比只收藏摘要更有用。

至少留下论断对应的页码/图表，区分作者陈述、自己的解释和待核实信息。按任务、数据、预算与评估协议比较工作，避免把不可比分数排成名次；模板见[可核查笔记](reading.md#paper-notes)。


## 研究问题与选题

<a id="q36"></a>

### 36. 初学者需要独立提出研究问题吗？参与已有课题能学到什么？

不必先独立提出一个完整的研究想法，才能参与研究。加入已有课题，可以学习一项工作如何推进、实验如何检查、文章如何组织，以及团队如何合作。

在阅读、实践和讨论中留意自己好奇的现象，研究想法往往由此产生。

<a id="q37"></a>

### 37. 研究方向、研究问题、想法与方法，这几个概念有什么区别？

- **研究方向：**宽泛领域，例如视觉、强化学习或语言模型。
- **研究问题：**关于任务、现象或假设的一项具体不确定性。
- **想法：**一种可能的解释、设计或调查思路。
- **方法：**定义清楚的研究程序或论证，例如算法、实验、证明或分析。

方法应回答问题，证据决定哪些结论成立。给一个新组件命名，本身还不是研究问题。


<a id="q38"></a>

### 38. 为什么别人读论文能发现问题，我读完只觉得“做得真好”？

这既来自经验，也来自对领域背景的熟悉。可以和更有经验的人读同一篇文章，比较你们注意到了什么。对方注意到的细节，可能是你此前没有考虑过的。比起直接记住“这篇工作有问题”，更值得弄清楚对方为何关注这里、依据是什么。

对自己好奇的地方，也可以先查阅资料或运行一个小实验。能提出一个具体疑问，再验证它，比逼自己立刻批判整篇文章更容易开始。

<a id="q39"></a>

### 39. 有了一个想法，怎么判断别人是否做过、它有没有意义，以及自己能不能做？

是否有人做过，最基本的就是调研。比较相近工作的任务设定、研究动机与方法细节，不能只靠关键词判断是不是重复。

你自己觉得好奇的问题，值得先去探索。但如果希望它成为一项能让别人也有所收获的研究，就要进一步追问：它能带来什么新的知识或更一般的理解？前人已经回答了哪些部分，还有什么没有解释清楚？

能不能做，也取决于资源：验证这个问题需要哪些数据、工具、算力、时间和合作？可以先挑一个小实验摸清条件。

小实验适合检查实现和成本，却未必足以证明新颖性、机制或普遍有效。将问题、假设、对照与反驳条件写成一页计划，见[从兴趣到可检验的问题](research-methods.md#question-hypothesis)；数据获取与划分可查[数据集指南](datasets.md)。


<a id="q40"></a>

### 40. 怎样判断一个问题值得继续投入？发现有人做过，或者初步尝试没效果，就应该放弃吗？

对前人报告过的失败，先核对具体条件与原因，不把“大家都试过了”的传闻当成结论。如果自己的初步尝试没有效果，先分清是实现存在问题，还是想法在当前条件下没有达到预期，再进一步分析原因。

没有达到预期同样能提供信息。继续分析后，即使仍未得到预期结果，也应记录在这些条件下观察到了什么。清楚保存条件、过程和观察，本身也可能带来新的发现。

停止一项尝试，并不会让已经得到的信息失去价值。接下来可以缩小问题、换一种解释，或把精力放到别处。

继续投入也需要考虑信息价值、机会成本与资源上限。把未观察到效果、估计精度不足和实现问题区分开，见[负结果与研究判断](research-methods.md#negative-results)。


## 实验与结果分析

<a id="q41"></a>

### 41. 拿到一个课题之后，怎样把“做研究”拆成今天、这周能执行的事情？

从想回答的问题往回拆：你想说明什么，需要什么证据，哪些实验能提供这些证据，还缺什么数据和基线方法。

第一阶段通常可以先读最相关的几篇文章、运行基线、弄清评估方法，然后选一个小问题验证。每天的任务写到能实际动手的程度。

<a id="q42"></a>

### 42. 为什么要运行基线、复现已有工作？跑通了代码之后，还要检查什么？

需要先明确参照，才能判断改动产生了什么影响。[结合论文读代码](reading.md#paper-code)，也会让数据、指标和实现细节变得具体。

跑通后，对照论文的设置与结果，检查数据划分、评测、随机性和是否泄漏。打开实际输出看一看，有些错误无法从总分中看出来。

区分成功安装并运行程序、复现某张表中的结果，以及验证论文主要结论这几种目标。先保存代码、数据和模型版本，再按同一协议检查基线；不能复现的差异应报告而非隐藏。可结合[回读研究设计的方法](research-methods.md#reproduction-checklist)和[数据划分指南](datasets.md)，判断差异可能来自哪里。


<a id="q43"></a>

### 43. 一个实验开始之前，应该明确什么？怎样避免不断跑实验，却不知道自己在验证什么？

先写清**验证的问题、预期结果，以及不同结果会怎样改变你对问题的理解**。先用小规模检查流程，再决定投入更大实验。

想判断一个因素的作用时，尽量控制其他条件；如果研究的是多个因素之间的关系，就按目的设计组合实验。每次改动都要能追溯。

同时记录数据划分、选择配置的规则、训练与推理预算、运行 ID 和原始输出位置。验证集用于选择方案，预留的测试数据不应反复用于调参；可参考[简短决策记录示例](research-methods.md#experiment-record)整理主要选择，开展实验时再按需要保留详细运行记录。


<a id="q44"></a>

### 44. 指标提高了，就说明想法有效吗？怎样排查实现错误、不公平比较、偶然波动等问题？

先查实现、数据划分和评价过程，再查比较是否公平，包括数据与额外信息、资源、配置、调参机会、候选与重试预算。一个更高的总分本身不能排除这些替代解释。

报告效应大小及与研究问题匹配的不确定性。不能只把平均提升与跨运行的标准差直接比较，就决定“有效”或“无效”；判断取决于样本数、配对方式、依赖结构和分析假设。使用多个随机种子可以描述固定数据下的运行波动，但不会创造新的独立患者、用户或任务；误差条需说明统计单位与计算方法。

再用有针对性的消融、失败分析和必要的独立评估检验解释。相关原则与示例见[不确定性与统计单位](research-methods.md#uncertainty)。


<a id="q45"></a>

### 45. 实验失败、复现不出来、连续几周没进展时，怎么定位问题，什么时候应该求助或调整方向？

缩小问题范围，从数据、实现、环境和评测逐步检查。把已经尝试过的方法和结果整理出来，向合作者或原作者请教。

确实可能遇到无法复现的结果。把条件与差异记清楚，再决定继续排查还是换参照；也提醒自己将来留下足够完整的复现信息。

## 交流与合作

<a id="q46"></a>

### 46. 遇到困难时，什么时候应该求助？

困难已经影响正确性、权限判断、他人的任务，或造成明显资源消耗时，就应求助。说明目标、实际现象、相关环境或来源、已经尝试的办法，以及需要帮助的准确位置；同时说明哪些独立工作可以继续。

按约定的反馈方式沟通，不必等到独自尝试了某个固定时长后才求助，也不必先用尽 AI 工具。清楚的问题有利于协作，但新手不需要先解决问题才有资格提问。


<a id="q47"></a>

### 47. 怎样把问题讲清楚，让他人能够帮助？

说明四件事：**目标是什么，试过什么，实际看到什么，以及还不确定什么。** 附必要的环境、版本、日志或结果，把问题缩小到可理解的范围。

代码问题尽量提供最小示例；论文问题注明版本与原文位置。具体组织方法见[学术联系与合作](contact.md)。

<a id="q48"></a>

### 48. 周会、组会、进度汇报到底汇报什么？没有正结果时，还能汇报什么？

讲这段时间做了什么、得到什么认识、接下来准备做什么。没有正结果，也可以讲排除了哪些可能、当前困难在哪里、需要什么帮助。

把一两个关键结果和原始记录带上。及时、清楚地同步进展，比等到得到理想数字后再汇报更有利于合作。

<a id="q49"></a>

### 49. 听不懂讨论或对结论有疑问，怎样追问？

指出具体术语、假设或推理步骤，询问能否用当前任务的例子解释。也可以记录后在约定的交流渠道继续讨论。

有不同意见时，说明自己的理解与证据：“按这个解释，我预期看到 A，但当前实验是 B。能否一起检查这个条件？”将分歧转化为可检查的问题。

<a id="q50"></a>

### 50. 合作时，任务、贡献、署名和时间预期应该什么时候讨论？遇到分歧怎么办？

开始合作时先谈：谁负责什么、各自投入多少、目标是什么、署名怎样按贡献讨论。中途任务和贡献变了，再同步更新。

有分歧时，先与相关合作者沟通，必要时找共同的指导者协调。尽量留下清楚的书面约定。

## AI 辅助研究

<a id="q51"></a>

### 51. 读论文、写代码、做实验、探索想法和写作，分别可以怎样借助 AI？

读论文时，让它解释概念、公式和背景，再回原文看依据。写代码时，让它起草脚本、排查错误，核心计算和评测要理解。做实验时，让它整理记录、作图、帮助分析。

探索研究想法时，可以与它讨论自己的问题，查找可能的相关工作，并检查解释中的漏洞。写作则用来理顺结构和句子，同时确认每个论断对应自己的证据。

<a id="q52"></a>

### 52. AI 给了一个听起来很合理的解释、方案或结果，我怎么判断它是否可信？

先查看原始记录。它说实验成功了，就看配置、日志、输出和统计；它说文章支持某个结论，就回到文章对应的位置。

一个方案听起来有道理，还需要设计能够检验它的实验或分析。遇到不符预期的地方，保留疑问，不急于让 AI 给出一个看似完整的解释。

<a id="q53"></a>

### 53. 使用 AI 时，理解方案、指标与实现细节有什么作用？

理解这些细节，才能向他人解释为什么这样选择、指标测量了什么、哪里可能出现问题，也更容易在条件变化后调整方案。

即使 Agent 已经跑完实验、画好了图，你还需要理解结果意味着什么，哪些地方值得怀疑，下一步该验证什么。人的参与不只是检查 AI 有没有出错，也包括发现意外、重新判断问题、决定如何推进。执行可以交给 AI，但这些判断和调整，才会慢慢变成你自己的经验。

<a id="q54"></a>

### 54. 怎样把一次借助 AI 完成的任务，变成自己的经验和直觉？怎么发现自己只是跟着它走？

做完后回看一次：原来怎么想，实际发生了什么，哪个判断错了，下次会先查哪里。保留一个具体例子，过段时间再看。

第一次写稿即使有 AI 协助，也可能经历很多困难；如果复盘后更清楚实验、论证和协作中的问题，下次就多了一份可以检验的参照。过程是否顺利、会遇到哪些困难，因人和任务而异。


<a id="q55"></a>

### 55. 哪些材料可以交给 AI，哪些需要先确认权限？论文里使用 AI 时，需要注意什么规范？

核对项目允许共享什么材料，以及所选服务如何处理资料。材料公开可见、笔记由自己撰写，或工具能够访问本地文件，都不等于已获准上传。共享文件与工具权限只开放当前任务所需范围。

写作或审稿时，遵循目标会议或期刊当年的 AI 辅助使用、保密与披露规则。[ICML 2026 政策](https://icml.cc/Conferences/2026/LLM-Policy)只是一个特定年份的例子，不是通用规定；作者与评审仍需对判断负责。

核实参考文献；生成的数据、标签或评分进入方法时，明确说明。相关方法见 [AI 使用与披露](writing.md#ai-disclosure)和[研究责任](research-methods.md#ethics-license)。


## 论文与研究成果

<a id="q56"></a>

### 56. 一项工作做到什么程度，才适合开始写论文？写作在研究过程中起什么作用？

“工作扎实”可以具体理解为：主要问题和主张清楚，有相匹配的论证或实验，关键替代解释得到检查，并诚实说明限制。是否适合投稿还取决于贡献类型与目标会议或期刊的范围和要求，不能由统一实验数量或分数门槛决定。写作和学术汇报的作用，是把这些观点、证据和做法清楚地传达给读者与听众。

不必等所有实验结束才动笔。早期就可以写问题、图和结果记录，帮助自己看清还缺什么。一段文字讲不清楚，可能是表达存在问题，也可能是研究本身还有未想清楚的地方。

开始写作不等于已经具备投稿条件。可用[主张—证据大纲](writing.md#claim-evidence)逐项检查，再按当年的投稿、匿名和配套研究材料的要求准备。


<a id="q57"></a>

### 57. 什么是好的研究、好的论文？有新方法、指标更高、发在好会议，分别能说明什么？

看一项研究好不好，重要的是**它为研究社区增加了什么**：有没有提出值得关注的问题，带来新的认识和知识，或者改变大家对已有问题的理解？

新方法是一种可能的贡献，指标更高也是一种证据，但它们都需要放回问题和实验条件里看。在某个基准上取得更高分数，不一定意味着已经弄清楚为什么变好；相反，有些工作不提出新模型，却能通过仔细的分析让大家重新认识一个现象。

在设有同行评审的投稿类别（track）中发表，说明工作经历了该类别的审稿与筛选；具体机制因会议和投稿类型而异。但会议名气不能代替对研究本身的判断。至于升学、评奖和成果认定，则还需要按具体学校和项目的规则来。


<a id="q58"></a>

### 58. 怎样区分期刊、会议、Workshop、预印本与地区性评价目录？

发表形式、引文索引与机构评价目录回答不同问题。阅读时按问题与证据选工作；申请或岗位确有要求时，再核对正式认可规则。

SCI/SCIE 与科学引文索引体系有关，当前可从 [Clarivate 的 Web of Science 索引说明](https://webofscience.help.clarivate.com/Content/wos-core-collection/wos-core-collection.htm)核对 SCIE。期刊是否收录、某年某学科的 JCR 排名/分区，以及其他机构的分区，是不同信息，不能混成同一个等级；查询时注明体系和年份。

作为地区性目录的例子，中国计算机学会的推荐目录对会议与期刊分类，其中包括 CCF A 类。目录会修订，具体范围与名称应查 [CCF 官方发布](https://www.ccf.org.cn/Academic_Evaluation/By_category/2024-06-28/825349.shtml)及其后续更新，不能只看第三方速查表。学校或项目如何认定，还需查看自己的正式规则。

“顶会”是领域内的习惯称呼，不是统一认证。NeurIPS、ICML、ICLR、CVPR、ACL 等覆盖不同研究范围；会议名称、某个投稿类别的评审性质与评价目录中的分类不能互相替代。

Workshop 是专题交流场合，是否同行评审、正式归档、接受何种工作，以及后续能否扩展投稿，都取决于具体规则；不能一概视为主会论文或非正式交流。

预印本是一种公开传播的论文版本或状态，不是质量等级。[arXiv 官方说明](https://info.arxiv.org/help/moderation/index.html)明确其内容审核不等于同行评审。已有正式发表版本的论文也可能保留 arXiv 版本；核对实际阅读版本、发表记录与相关政策，见[论文版本与发表状态](reading.md#search-protocol)。


<a id="q59"></a>

### 59. 暂时没有论文或投稿被拒，怎样检查自己的进步？

将具体能力与原始记录对应起来：是否能独立分析论文、修正一次数据泄漏、让同伴重跑一张图，或发现证据不足后缩小结论？这些变化比单纯计算投入时间更便于评估。

没有完成的研究也应说明停在哪里、留下了什么，以及是否值得继续。研究经历不保证升学或就业结果，但可检查的作品能够具体呈现已经完成和学到的事情。

<a id="q60"></a>

### 60. 一个项目推进不下去时，怎么判断该继续、调整方向，还是暂时停下来？

先看看当前遇到的究竟是什么问题：是最初的假设不成立，实验一直无法支持判断，还是数据、算力、时间和协作条件发生了变化？这些情况需要的处理并不一样。

如果问题仍然值得研究，但现有条件做不了，可以先缩小范围，寻找更容易验证的一部分；如果已经反复检查，证据也不支持原来的想法，可以调整解释，甚至换一个问题。停下来并不会让已有的观察失去价值。

无论继续还是结束，都应清楚保存做过的实验、失败的尝试、代码和未解决的问题。有合作者时，也要沟通后续安排。决定不应仅凭一时的结果好坏，而应考虑继续投入能否获得新的信息。
