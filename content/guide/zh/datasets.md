# 数据集、基准与评测方法

数据集（dataset）是数据资源；基准（benchmark）还规定任务、划分、指标及比较协议。下载了同一份数据，不代表进行了可比较的实验。先写清研究问题与目标场景，再选择数据和评测方法。

本页于 **2026-10-16** 查阅下列官方入口与文档。它们是学习和研究的候选资源，不是对数据质量、授权范围或长期可访问性的担保。具体版本、许可、下载条件和任务规则应以原项目为准。完整实验流程见[实验设计与可复现研究](research-methods.md)。

## 先选任务，再选数据

| 任务 | 适合起步的比较 | 需要先固定的条件 |
| --- | --- | --- |
| 表格分类或回归 | 常数预测、线性模型、树模型 | 样本单位、缺失值处理、组别或时间划分 |
| 图像分类、检测、分割 | 规定输入大小的简单模型或公开实现 | 类别、标注格式、数据增强、预训练数据 |
| 文本分类与阅读理解 | 稀疏特征基线、较小预训练模型 | 分词、长度截断、标签与评分脚本 |
| 检索与 RAG | 词项检索与稠密检索；先单独评估检索 | 语料版本、查询、相关性标注、切块和 top-k |
| 语言模型与工具 Agent | 固定模型与任务的简单提示或规则流程 | 提示、工具权限、重试次数、预算与终止条件 |
| 强化学习与机器人 | 简单控制器、行为克隆或标准算法 | 环境版本、训练交互量、评估种子、成功条件 |

学习项目优先选择可检查、规模适中的公开数据。使用更大的数据集应服务于研究问题；下载规模本身不构成研究贡献。

## 数据发现与加载工具

- **[UCI Machine Learning Repository](https://archive.ics.uci.edu/)** — 表格等机器学习数据入口，适合练习数据描述、分类和回归。逐项阅读变量含义、目标定义、引用与许可；不能对同一仓库中的不同数据套用同一组默认假设。
- **[OpenML 与官方文档](https://docs.openml.org/)** — 将数据、任务、模型流程与运行结果关联起来。比较实验时记录 dataset ID、task ID、版本和指定划分，避免把自行划分的结果与既定任务结果混在一起。
- **[Hugging Face Datasets](https://huggingface.co/docs/datasets/en/index)** — 文本、图像、音频等数据的加载与处理库，可结合 Hub 检索数据。固定仓库 revision、配置、split 和预处理；平台托管不等于平台为所有数据授予相同使用许可。
- **[Torchvision Datasets](https://docs.pytorch.org/vision/stable/datasets.html)** — 包含 MNIST、Fashion-MNIST、CIFAR 等数据接口，以及构建图像数据集的基础类。适合从小型视觉实验起步；区分数据本身、加载器、数据增强与评分实现的版本。
- **[TensorFlow Datasets](https://www.tensorflow.org/datasets/overview)** — 提供多种任务的数据构建器与加载接口。记录 builder、配置、版本和划分；使用加载工具不能替代对原数据说明与条款的阅读。

## 视觉、语言、语音与图数据

- **[COCO](https://cocodataset.org/)** — 目标检测、分割、关键点与图像描述等任务资源。使用对应任务的标注和官方评测实现，写明年份、split、IoU 阈值与预测数量等设置；不要将 AP50 与 COCO 主 AP 直接视为同一指标。
- **[ImageNet](https://www.image-net.org/)** — 图像分类与视觉表示研究的重要数据来源。明确使用的是哪个子集与挑战协议，并核对访问和使用条款。初学者可先通过小型数据练习完整流程，无需直接从大规模训练开始。
- **[GLUE](https://gluebenchmark.com/)** — 多任务语言理解基准，定义与任务背景见[原始论文](https://arxiv.org/abs/1804.07461)。适合学习任务间比较；总体分数不能代替逐任务分析，也不能直接代表开放环境中的通用可靠性。
- **[SQuAD](https://rajpurkar.github.io/SQuAD-explorer/)** — 基于段落的阅读理解；SQuAD 2.0 还包含无法由段落回答的问题。使用匹配版本的评分脚本，区分答案字符串匹配、词级 F1 与真实任务中的事实准确性。
- **[LibriSpeech / OpenSLR](https://www.openslr.org/12)** — 朗读英语语音与转录资源，可用于学习自动语音识别。保留官方训练、开发与测试划分，说明文本规范化、分词及词错误率的计算方式；朗读语音表现不能直接外推到噪声对话或其他语言。
- **[Open Graph Benchmark](https://ogb.stanford.edu/)** — 图机器学习的数据、加载器与评估器，覆盖节点、边和图级任务。使用指定划分与评价规则，区分随机划分、时间划分和跨结构泛化问题。

## 检索、语言模型与 Agent 评测

- **[BEIR](https://github.com/beir-cellar/beir)** — 跨数据集的信息检索评测框架，适合比较词项检索与稠密检索。记录查询、语料与 qrels 版本，并报告逐数据集结果；相关性标注可能不完整，未标注不一定等于不相关。
- **[MTEB](https://github.com/embeddings-benchmark/mteb)** — 表示与检索等任务的评测工具，包含多语言及多模态任务。固定任务集合和版本，核对模型输入格式、提示和指标；采用不同聚合方式或任务版本的榜单分数，不宜直接横向比较。
- **[SWE-bench](https://www.swebench.com/)** — 面向真实软件问题修复的基准。比较时明确使用的变体、任务集合、运行环境和资源预算；通过指定测试的比例，不能说明软件的所有质量与安全属性都已得到验证。

对 RAG，应分别记录检索召回、证据是否支持回答、答案质量与拒答表现；对 Agent，还应记录任务成功、失败类型、工具调用、重试和成本。模型评分器属于测量工具，应抽样与人工标注核对，检查顺序、长度、提示和语言带来的偏差。更详细的对照设计见[实验方法](research-methods.md)。

## 决策、机器人与系统性能

- **[Minari](https://minari.farama.org/)** — 离线强化学习数据标准与工具，包含基于轨迹的资源。学习时检查 episode、终止与截断、行为数据来源及环境兼容性；离线评估与实际环境中的在线回报反映不同层面的表现。
- **[Open X-Embodiment](https://robotics-transformer-x.github.io/)** — 多种机器人平台的操作数据与模型研究入口。比较数据格式、观测、动作空间、控制频率与任务定义；不同机器人的轨迹不能直接当作同质样本拼接。
- **[MLPerf Inference Datacenter](https://mlcommons.org/benchmarks/inference-datacenter/)** — 在规定任务、质量要求与场景下衡量推理系统表现。比较结果必须核对版本、场景、质量目标、硬件和软件设置；吞吐量与延迟不是可互换的指标，也不能脱离模型质量单独解释。

## 指标选择与常见误读

指标定义与实现可查阅 [scikit-learn 评价文档](https://scikit-learn.org/stable/modules/model_evaluation.html)和具体基准的评分器。对于 precision–recall 曲线，应明确报告采用的是 [average precision（AP）](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html)还是梯形积分面积，以及实现与插值规则；二者不能不加说明地当作同一个 PR-AUC 横向比较。下面是选择指标时的基本问题；不存在适用于所有任务的单一“最好”指标。

以下是一个为说明指标而构造的二分类例子：100 个样本中有 10 个真实正类。某方法找出其中 8 个、漏掉 2 个，并把 90 个负类中的 18 个误报为正。**精确率为 8/26 = 30.8%，召回率为 8/10 = 80%，准确率为 80/100 = 80%。** 全部预测为负可以达到 90% 准确率，却找不到任何正类。哪种表现有用，取决于任务与错误代价。比较分数前，先明确正类并检查计数。

| 任务 | 常见指标 | 必须同时解释 |
| --- | --- | --- |
| 不均衡分类 | precision、recall、F1、PR-AUC；必要时 ROC-AUC | 正类定义、阈值、类别比例、macro/micro/weighted 聚合 |
| 回归 | MAE、RMSE、R² | 目标单位、异常值、数据范围及相对简单基线的改进 |
| 概率预测 | log loss、Brier score、校准分析 | 区分概率质量、分类阈值与排序能力 |
| 检索排序 | Recall@k、MRR、nDCG@k | 候选语料、相关性等级、截断 k 与查询分布 |
| 检测与分割 | AP、IoU、Dice | IoU 阈值、类别和样本聚合、小目标及稀有类表现 |
| 文本与图像生成 | 任务指标、参考匹配或分布指标、人工评价 | 单一自动分数不能同时证明事实性、多样性、感知质量与实用性 |
| 决策与系统 | 成功率、回报、延迟、吞吐、资源用量 | 预算、失败处理、评估任务与质量约束 |

同一模型在不同随机种子下的均值与标准差反映运行差异，不能自动解释为总体置信区间。要说明不确定性来自数据抽样、训练随机性、任务选择还是人工标注，并采用与依赖结构相符的分析单位。

## 数据审计与许可记录

在训练前完成以下记录；数据卡可参考 [Hugging Face Dataset Cards](https://huggingface.co/docs/hub/en/datasets-cards)。本清单是科研记录建议，不能替代对具体协议和机构要求的核对。

1. **来源与用途：** 创建者、原始入口、采集方式、预期用途和已知排除场景。
2. **版本与完整性：** 下载日期、版本或 revision、文件校验值、过滤与去重规则。
3. **样本与标注：** 样本单位、标签定义、缺失值、噪声、标注过程及代表性限制。
4. **划分与污染：** 组别或时间依赖、重复样本、训练与评测的交叉，以及基础模型训练数据不透明带来的未知项。
5. **权限与隐私：** 许可、署名、再分发条件、个人信息和访问控制；代码许可不自动覆盖图片、语音、文本或权重。
6. **计算成本：** 下载、解压、缓存、预处理、存储和完整评估的成本。

## 读懂一份评测记录

阅读论文或准备报告时，检查以下五个方面及其联系：

| 内容 | 为什么重要 |
| --- | --- |
| 任务与目标总体 | 定义成功与泛化意味着什么 |
| 数据版本与划分规则 | 明确学习和评估能够接触什么信息 |
| 选定的系统与预算 | 包括预处理、提示、工具与调参机会 |
| 评估程序与原始结果 | 使指标定义、分母、失败处理与聚合方式可供核查 |
| 不确定性与限制 | 区分观察到的差异与范围更广的主张 |

这些选择如何联系起来，可参考[简短决策记录示例](research-methods.md#experiment-record)。学习时，可以先给一篇论文的评估部分作批注，指出一项缺失信息；撰写自己的项目报告时，再补充逐类别或逐任务的结果，以及有代表性的失败案例。基线数量应由问题决定，不必统一规定。测试结果一旦影响提示、阈值或模型选择，就应说明这种使用，并对修改后的流程开展独立评估。
